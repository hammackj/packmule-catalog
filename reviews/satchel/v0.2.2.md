## Satchel v0.2.2 review

**What it does:** Satchel is a single-window bag addon. It has an inventory/bank view, sorting, and a "Sell junk" button that only appears at a vendor.

**Changes from v0.2.1 (CHANGES.diff):**
- `Satchel.lua`: `sellRun` is now incremented at the start of `sellJunk()`, so every click cancels a queue that is still running. It is also incremented in `MERCHANT_CLOSED`, so a queue stops when the vendor window closes.
- The CHANGELOG and TOC version strings changed. The CHANGELOG contains "Co-Authored-By" and session-URL lines, which are ordinary commit trailers. There is no text aimed at a reviewer.
- This is a hardening change. It narrows when sales can happen and adds nothing new.

**Pre-scan hits checked:**
- `Satchel.lua:267-268`: `C_MerchantFrame.SellAllJunkItems()` is Blizzard's sell-all-grey-items call. It runs only after the player clicks the button, and only when no protected items would be sold.
- `Satchel.lua:283`: `C.UseContainerItem` sells grey items one at a time. It runs only after the click and only while `atMerchant` is true. Each sale re-checks the item link, quality, value, lock and protection. Items marked protected are skipped. This is normal vendor-junk behaviour.
- `Sort.lua:139-140`: `PickupContainerItem` swaps bag slots for sorting. It stays within the player's own bags. I did not read the surrounding code in detail. The prescan listed only these two calls, and the diff did not touch this file.

**Other risk categories:** The pre-scan flagged no mail, trade, auction, guild bank, chat, `SendAddonMessage`, `loadstring`, macro, or delete calls. It also flagged no non-addon files in the zip. The diff touches only the files above.

**Coverage:** I read the full diff, the pre-scan, and the sell-junk code (`Satchel.lua` lines 225-304). I did not read the other files, which the task treats as already reviewed.

**Concerns:** None.

## Codex

Satchel combines bag and bank windows, remembers characters’ inventory and gold locally, and provides sorting, item protection, and junk selling.

Reviewed the complete release diff, all five Lua files, metadata, and every prescan hit. File references below are relative to `builds/Satchel-v0.2.2-forever/Satchel/`.

- **Junk selling:** `Satchel.lua:267–268` calls `SellAllJunkItems()` only when no protected grey items were skipped. The fallback at `Satchel.lua:276–283` sells on timers after the player clicks “Sell junk” (`:294`), checking the merchant state, original item link, grey quality, value, lock, and protection before each sale. Normal vendor functionality.
- **Release changes:** `Satchel.lua:264` cancels earlier sale queues on every sell click; `:418–420` cancels them when the merchant closes. These changes prevent stale queued sales from resuming.
- **Item movement:** Both `PickupContainerItem` hits (`Sort.lua:139–140`) move items between bag slots for stacking and sorting. Sorting starts from the Sort button (`Window.lua:466–472`), with cursor/lock checks, combat cancellation, and a timeout. No deletion or transfer to other players.
- **Chat and player data:** `Window.lua:339–341` handles player-requested modified item clicks. Status messages use local `print`. Character inventories and gold stay in `SatchelDB` (`Data.lua:16–74`); diagnostics are also stored locally. No outgoing chat, addon messages, or incoming message handlers were found.
- **Commands and hidden execution:** `/satchel` changes display settings, toggles bags, and manages local saved records (`Satchel.lua:476–535`). No string execution, obfuscated payloads, macro/key-binding changes, forced logout, mail/trade/auction automation, or bundled executable scripts were found.
- **Deception:** No reviewer-directed instructions or phishing content found. The changelog’s project links and AI coauthor/session attribution are documentation, not instructions to the reviewer.

No malicious behavior or unresolved security concern identified in this static review.

VERDICT: PASS (nothing malicious)
