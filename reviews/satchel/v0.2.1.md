## Claude

**Satchel v0.2.1 review**

**What it does:** Satchel is a bag addon that puts all bags in one window. It also has sorting, gold across characters, BoE labels, upgrade arrows, protected items and a "sell junk" button.

**Changes from v0.2.0:** I read `CHANGES.diff`. It touches three files:
- `CHANGELOG.md` and `Satchel.toc` only have version and text updates.
- `Satchel.lua` changes only the junk-selling fallback queue. This is the change the changelog describes.
  - Each queued slot now also stores the item's hyperlink.
  - A `sellRun` counter means a second click replaces the running queue. A stale queue stops.
  - Before each `C.UseContainerItem`, the code re-reads the slot. It sells only if the hyperlink matches, `quality == 0` (grey), the item has a vendor value, it isn't locked, and it isn't protected.
  - This makes selling stricter than before. The previous code sold by remembered slot with no check. Sales still happen only at a merchant, after the player clicks.

**Risky behaviours checked:**
- **Prescan:** it reported no risky API hits and no unusual files.
- **Gold or item theft:** the diff adds no mail, trade, guild bank or auction calls. `UseContainerItem` at a vendor, limited to grey unprotected items, is normal junk selling.
- **Item destruction:** there are no `DeleteCursorItem` calls in the diff.
- **Chat, addon messages, data leaks:** none added.
- **Hidden code:** there is no `loadstring`, `load` or `RunScript`, and no obfuscated blobs in the changed code.
- **Phishing, macros, key bindings:** none added.
- **Prompt injection:** the changelog mentions "Packmule code review" and carries a Claude co-author trailer. It is ordinary commit metadata and gives no instructions to a reviewer, so I didn't treat it as a finding.

**Concerns:** None.

VERDICT: PASS

## Codex

Satchel combines bags and bank storage into searchable windows, remembers characters’ inventory and gold, sorts items, and sells vendor junk. I reviewed the v0.2.1 diff and full changed files, treating unchanged code as previously reviewed. File references below are under `builds/Satchel-v0.2.1-forever/Satchel/`.

- **Vendor sales:** `Satchel.lua:294` binds selling to the “Sell junk” click. Line 267 calls `SellAllJunkItems()` only when no protected grey items were skipped. The fallback at lines 276–283 delays sales but checks merchant state, queue identity, matching item link, grey quality, value, lock and protection before `C.UseContainerItem(...)`. This is normal, player-requested selling.
- **Item movement:** `Sort.lua:139–141` uses `PickupContainerItem` and `ClearCursor` for sorting, triggered by the Sort button (`Window.lua:467–468`). No item destruction or transfer to another player was found.
- **Messages and player data:** `Window.lua:341` calls `HandleModifiedItemClick(self.link)` following a player click. Status messages use local `print` (`Satchel.lua:29`). Character information and gold remain in saved variables (`Data.lua:16–23,48–64`); diagnostics also stay local (`Debug.lua:17–35`). No unsolicited messaging or data transmission was found.
- **Hidden code and packaged files:** No string execution, obfuscated payload, mail/trade/auction abuse, macro or binding changes, forced logout, or external executable was found. Changelog links and AI attribution are documentation, not instructions addressed to a reviewer.

**Concerns:** `REVIEW_PRESCAN.txt` reports no risky APIs, but misses the sale and movement calls checked above. Also, queue cancellation is incomplete: the native sale branch returns before `sellRun` increments (`Satchel.lua:266–273`), and merchant closure does not invalidate the queue (`418–420`). Pending callbacks could survive a rapid close/reopen, although each still requires a matching, unprotected, sellable grey item. This is a minor correctness issue, not evidence of malicious behavior.

VERDICT: PASS (nothing malicious)
