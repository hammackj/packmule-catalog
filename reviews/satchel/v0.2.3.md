## Claude

# Satchel v0.2.3 review

**What it does:** Satchel is a single-window bag addon. It handles sorting, bank display, junk selling and item locks (protected items).

**Changes since v0.2.2** (CHANGES.diff, four files):
- `Satchel.toc` and `CHANGELOG.md`: version bump and changelog text only.
- `Debug.lua`: adds `MerchantSellAllJunkButton` and `C_MerchantFrame` to a list of globals the debug probe records. This is a diagnostic only.
- `Satchel.lua:293-309`, new `hookVendorButton()`, called from `MERCHANT_SHOW`:
  - It replaces the OnClick of Blizzard's vendor "Sell All Junk" button.
  - If the player has locked grey items, it runs Satchel's own sell queue, which skips those items.
  - Otherwise it calls Blizzard's original handler unchanged.
  - It only runs on the player's own click, and it prints a visible chat message to the player.
  - It can only sell grey items, and it is stricter than Blizzard's button because it leaves locked items alone. This is not a finding.

**Pre-scan hits:**
- `Satchel.lua:267-268`, `C_MerchantFrame.SellAllJunkItems()`: this is Blizzard's sell-all. Satchel only calls it when no protected greys were skipped. It runs from a player click on the junk button or the vendor button, so it is not silent.
- `Satchel.lua:283`, `C.UseContainerItem`: this is the queue that sells grey items one at a time. Each sale first checks that:
  - the merchant window is still open,
  - the slot still holds the same grey item,
  - the item is not locked, and
  - the item is not protected.
- `Sort.lua:139-140`, `PickupContainerItem`: these swap items between bag slots as part of sorting. Nothing leaves the bags.

**Other checks:**
- I grepped the whole build for `loadstring`, `RunScript`, `load(`, `SendAddonMessage`, `SendChatMessage`, `SendMail`, `DeleteCursor` and escaped byte sequences. There were no matches.
- The zip holds only the 8 files above: Lua, the TOC, LICENSE and CHANGELOG. There are no executables or scripts.
- I found no text addressed to a reviewer or an AI. The changelog's "Co-Authored-By" line is an ordinary commit trailer.
- I read the sell, junk and hook code in full. I did not read Data.lua, Window.lua, Debug.lua or the rest of Sort.lua line by line. The earlier version passed review, and the grep found nothing in them.

**Concerns:** None.

VERDICT: PASS

## Codex

Satchel combines bags and bank storage into searchable windows, remembers characters’ inventories and gold locally, sorts items, and sells vendor junk.

Reviewed the complete v0.2.3 diff, all five Lua files, the manifest, release text, and every pre-scan hit. File references below are within `builds/Satchel-v0.2.3-forever/Satchel/`.

- **Vendor sales:** `Satchel.lua:267–268` calls `C_MerchantFrame.SellAllJunkItems()`. The fallback at `Satchel.lua:283` calls `C.UseContainerItem(...)` on a timer after a sell-button click. It rechecks item identity, grey quality, value, and protection; closing the merchant cancels pending sales. Normal junk-selling behavior.
- **New vendor hook:** `Satchel.lua:294–308` routes the vendor’s sell-button click through that queue when protected greys exist. This branch bypasses Blizzard’s original confirmation but preserves protected items and requires the player’s sell click. No malicious behavior found.
- **Item movement:** `Sort.lua:139–140` calls `C.PickupContainerItem(...)` to stack or rearrange items. Sorting starts through the Sort button (`Window.lua:467–468`), excludes protected slots, and checks cursor/item availability. No transfers to other players or item destruction.
- **Messages and stored data:** Character inventories and gold remain in `SatchelDB` (`Data.lua:16–74`); diagnostics also remain local (`Debug.lua:159–160`). Status messages use local `print`. Modified item clicks use `HandleModifiedItemClick` (`Window.lua:339–342`). No outgoing chat, Battle.net messaging, addon-message transmission, or incoming message handlers found.
- **Commands and hidden execution:** `/satchel` changes settings, opens bags, or clears local records (`Satchel.lua:499–558`). No string-executed code, obfuscated payloads, harmful macros/bindings, forced logout, phishing, or external executable scripts found. No instructions addressed to AI reviewers were found; the changelog’s AI coauthor attribution is ordinary metadata.

VERDICT: PASS (nothing malicious)
