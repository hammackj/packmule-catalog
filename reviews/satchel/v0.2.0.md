# Satchel v0.2.0 review

## What it does
Satchel replaces Blizzard's bag and bank windows with a single combined window. It has these features:
- Item-level, BoE and upgrade-arrow overlays.
- Search.
- A saved view of other characters' bags, bank and gold. This data is stored only in the local `SatchelDB` SavedVariables.
- Tooltip item counts across characters.
- Alt-click item protection.
- A "Sell junk" button at vendors.
- A custom sort that works around protected items.
- Debug and error logging written to SavedVariables.

The `.toc` loads five Lua files: `Debug.lua`, `Data.lua`, `Sort.lua`, `Window.lua` and `Satchel.lua`. I read all of them. The zip has no executables or scripts, only `LICENSE` and `CHANGELOG.md` besides the Lua and `.toc` files. `REVIEW_PRESCAN.txt` reported no risky API hits, and my own grep agreed.

## Risky behaviours checked
- **Gold and items:**
  - There is no mail, trade, guild bank or auction code.
  - `C.UseContainerItem` is called only in `sellJunk` (`Satchel.lua:272`). It runs only while `atMerchant` is true, only on grey-quality items, and only after the player clicks the "Sell junk" button (`Satchel.lua:283`). Items the player has protected are skipped.
  - `C.PickupContainerItem` is called only in `Sort.lua:139-140`. It moves items between the player's own bag slots, and the sort is started by the player's Sort button.
- **Destruction:** There are no `DeleteCursorItem` or similar calls. `Sort.lua:138` and `:141` call `ClearCursor`, which only clears the cursor.
- **Chat and messages:** There is no `SendChatMessage`, `SendAddonMessage` or Battle.net call. The only output is `print` to the player's own chat frame, for settings and status messages.
- **Data leaks:** Character, gold and bag data stays in the local `SatchelDB` and is shown only in tooltips and windows. Nothing is sent to other players.
- **Hidden code:** There is no `loadstring`, `load` or `RunScript`, no escaped-byte or base64-like blobs, and no long obfuscated lines. `Data.lua` is plain code, not a large data table.
- **Phishing and URLs:** There are no popups, links or URL strings in the Lua. The only URLs are the author's GitHub links in `CHANGELOG.md`.
- **Macros, bindings and logout:** None are touched.
- **Other behaviour:**
  - `Debug.lua` chains the error handler. It only logs error text to `SatchelDB.debug` and calls the previous handler.
  - `Debug.lua` also records which APIs the client has and the bank state. This is local only.
  - `Satchel.lua` re-parents Blizzard's bag frames and hooks bag functions with `hooksecurefunc`. This is normal for bag replacement addons.
- **Embedded instructions:** I found no text addressed to an AI or reviewer in the code. The changelog has `Co-Authored-By: Claude` and session-URL commit trailers. These are ordinary commit metadata, not instructions, and they aren't a concern.

## Concerns
None. All behaviour matches the addon's stated purpose.

VERDICT: PASS

## Codex

Satchel replaces the bag and bank windows, adds sorting and item protection, and remembers characters’ inventory and gold for local viewing. I read all five Lua files under `builds/`, plus the manifest and accompanying text.

`REVIEW_PRESCAN.txt` reports no hits, but manual review identified these relevant behaviors. File references below are relative to `builds/Satchel-v0.2.0-forever/Satchel/`.

- **Vendor selling:** `Satchel.lua:247–253` selects unprotected grey items. Lines 265 and 272 call `SellAllJunkItems()` or `C.UseContainerItem(...)`. This starts from the “Sell junk” button’s click handler at line 283. Ordinary player-requested vendor selling; no recipient or theft mechanism.
- **Timed item movement:** `Sort.lua:137–141` uses `PickupContainerItem` to rearrange items. Its timer loop at lines 247–275 follows the Sort button action (`Window.lua:467–468`), checks combat and timeout conditions, and waits for unlocked items. No item deletion or transfer to another player.
- **Item clicks and chat:** Live buttons forward player clicks to Blizzard’s item handler (`Window.lua:250–265`). Offline buttons call `HandleModifiedItemClick(self.link)` on click (`Window.lua:338–360`). No unsolicited chat, whispers, Battle.net messages, or addon messages were found.
- **Stored player data:** Character names, realms, inventory, equipment and gold are saved locally (`Data.lua:16–74`). Error logs also remain in `SatchelDB` (`Debug.lua:17–60`). No transmission path was found.
- **Hidden code and other threats:** No string execution, obfuscated payloads, mail/trade/auction automation, destructive APIs, macro or binding changes, forced logout, phishing, or external executable scripts were found. No text addressed to a reviewer or AI was found; the changelog’s AI coauthor credits are attribution.

**Concern:** The fallback selling queue saves bag/slot coordinates, then checks only `if atMerchant then` before `C.UseContainerItem(s[1], s[2])` (`Satchel.lua:269–274`). Moving or sorting items during that queue could cause a different, potentially valuable or protected item to be sold. Rechecking item identity, quality and protection immediately before each sale would address this accidental-loss risk. This appears to be a correctness bug, not malicious or deceptive behavior.

VERDICT: PASS
