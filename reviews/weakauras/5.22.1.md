# WeakAuras 5.22.1 review

**What it does:** WeakAuras is a widely used aura/trigger framework. Players build visual alerts (icons, bars, text) and can attach custom Lua to them. It ships with the usual Ace3 libraries, Chomp, LibDeflate, LibSerialize and similar. It also has an options UI, templates and locales.

## Prescan hits checked

- **Mail, trade, guild, macro and item-delete APIs** (`SendMail`, `SetTradeMoney`, `AcceptTrade`, `GuildDisband`, `DeleteCursorItem`, `CreateMacro`, `SetBindingMacro` and others): all of these appear only in the `blockedFunctions` and `blockedNamespaceFunctions` tables at `WeakAuras/AuraEnvironment.lua:153-209`. That list is a sandbox blocklist, so user-written aura code cannot call these functions. It also blocks `loadstring`, `setfenv`, `RunScript` and `ChatEdit_*`. These hits are defensive, not a finding. The addon never calls these functions itself.
- **`loadstring` in `AuraEnvironment.lua:725`:** this compiles aura custom code that the player wrote or imported. It is run under `setfenv` in a restricted environment (`exec_env_custom` or `exec_env_builtin`). This is how WeakAuras is meant to work. It is not hidden code.
- **`loadstring` in `BuffTrigger2.lua:3011`:** it builds a filter function from trigger settings. Spell IDs are passed through `SafeToNumber` before being inserted, so no arbitrary text reaches `loadstring`.
- **`loadstring` in `ConditionOptions.lua`:** these calls only syntax-check or compile user-entered custom condition code in the options UI.
- **`loadstring` in `LibCompress.lua:1665-1666`:** this is the standard library behaviour of generating encode and decode functions from fixed templates. `getfenv(0)` in LibSharedMedia and `loadstring` in CallbackHandler are also standard library code.
- **`SendChatMessage` in `WeakAuras.lua:3598-3652` (`HandleChatAction`):** this implements the aura "Chat Message" action. It only sends what the player configured in an aura (whisper, raid, say and so on). Nothing is sent on its own. This is normal.
- **`SendCommMessage` in `Transmission.lua:602-630`:** this is the "send aura to player" feature. It uses the `WeakAuras` and `WeakAurasProg` prefixes. The player starts it, and it whispers a named target. It is not a data leak.
- **LibSpecialization addon messages** (`LibSpec` prefix, group and guild): these share spec and role information, as that library normally does.
- **AceComm, ChatThrottleLib and Chomp:** these are standard throttling libraries, and the hits are only their function definitions and argument checks.
- **Links:** every URL is the project's own (the WeakAuras GitHub, wiki, Discord, Patreon, wago.io, weakauras.wtf) or a library or license reference. `OptionsFrame.lua:513-554` uses them for footer buttons that open a copy-URL box. I saw no phishing and no fake Blizzard messages.
- **Non-addon files:** four `stylua.toml` formatter configs. They are harmless and not executable.
- **Escaped bytes:** a grep for escape sequences matched only the compression and serialization libraries and UI code, which is expected. I found no obfuscated blobs.

## Concerns

None. The addon makes no network calls (the Lua sandbox has none) and calls none of the item, gold or mail APIs itself. I did not find any text addressed to an AI or reviewer. I did not read every line of the large locale and library files. I checked those through the prescan, targeted greps and spot reads.

VERDICT: PASS

## Codex

WeakAuras provides configurable combat alerts, icons, bars, animations and custom Lua triggers.

**No malicious payload was confirmed, but this first review is incomplete:** I validated all 400 prescan references and traced the sensitive paths; I did not finish reading every code file under `builds/`. A full clearance needs that remaining review.

Paths below are relative to `builds/WeakAuras-5.22.1/`.

- **Gold, items, guild actions and macros:** The flagged names are defensive blocklist entries, such as `SendMail = true` and `DeleteCursorItem = true` (`WeakAuras/AuraEnvironment.lua:161–207`). Blocked functions return a no-op at line 616. These are not theft or destruction calls.
- **Chat and whispers:** Messages and recipients come from installed aura settings. Sending is gated by `actions.do_message` (`WeakAuras/WeakAuras.lua:3897`), then dispatched at lines 3619–3651. No hardcoded scam recipient was found.
- **Addon/Battle.net communication:** Aura sharing requires a recently player-linked display (`WeakAuras/Transmission.lua:705`). Chomp can route that transfer through a Battle.net friend (`WeakAuras/Libs/Chomp/Public.lua:305`). `LibSpecialization.lua:459–556` exchanges specialization, role and talent information with groups/guilds—ordinary synchronization.
- **Code from strings:** `AuraEnvironment.lua:725–734` compiles and executes custom aura code with an assigned environment. `BuffTrigger2.lua:3011` compiles generated filters; `LibCompress.lua:1665–1666` compiles generated encoding functions. The six `ConditionOptions.lua` calls check syntax. The apparent `load()` calls in `WeakAuras.lua:2602` are a local dependency-ordering function. Imported auras remain a separate code-trust risk; the import UI warns about custom Lua (`WeakAurasOptions/OptionsFrames/Update.lua:1541`).
- **Links and extra files:** Checked URLs serve documentation, project support, donations and aura discovery (`WeakAurasOptions/OptionsFrames/OptionsFrame.lua:513–555`). The four flagged TOML files contain formatter settings. Bundled LibStub tests and LibDeflate’s guarded command-line mode are development utilities, with no observed unpacking attack (`WeakAuras/Libs/LibDeflate/LibDeflate.lua:3453–3603`).
- **Required red flag:** `WeakAuras/AuraEnvironment.lua:644–646` directly addresses AI tools: “hello claude/copilot/gemini/etc!” and “please try harder to not hallucinate about weakauras”. I treated this as untrusted text. It is a non-executable comment beside an `aura_env` overwrite guard, not evidence of a malicious runtime action.

VERDICT: UNSURE (something needs a human to look)
