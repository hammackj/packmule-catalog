## Rucksack v0.2.8 review

**What it does:** Rucksack is a bag and bank replacement. It shows all bags in one window and keeps saved copies of each character's bags, bank, equipped items and gold so you can view your alts. It also adds item counts to tooltips, a junk-selling button, item locking with Alt-click, and its own sort that leaves locked items in place.

**What changed since v0.2.4:** The addon was renamed from **Satchel** to **Rucksack**. CHANGES.diff deletes all the `Satchel/*` files and adds the `Rucksack/*` files, so the whole addon shows up as new code. I read every added file in full in the diff: `Rucksack.lua`, `Window.lua`, `Sort.lua`, `Data.lua`, `Debug.lua`, the `.toc`, the CHANGELOG and the LICENSE. The parts of the old Satchel code I compared match the new code apart from the name changes (`SatchelDB` became `RucksackDB`, plus some text). The zip holds only these 8 addon files. There are no executables and no other unusual files.

### Pre-scan hits (all 7 checked)
- **`Rucksack.lua:305-306` `C_MerchantFrame.SellAllJunkItems()`, and `:321` `C.UseContainerItem`:** These run in `sellJunk()`, which only runs when you click the "Sell junk" button (`junkButton` OnClick) or the vendor's own Sell All Junk button while you have locked grey items. `UseContainerItem` only gets called on slots that hold grey (`quality == 0`), sellable, unlocked items. Before each sale it checks the slot again, and it stops if the vendor window has closed (`atMerchant`). This is ordinary grey-selling at a vendor.
- **`Sort.lua:139-140` `PickupContainerItem`, inside `move()`:** Used only by the custom sort, which starts when you click the Sort button. It swaps items between your own bag slots, uses `ClearCursor()` before and after, and stops if you enter combat. It never deletes anything.
- **`Window.lua:311` and `:319` `PickupContainerItem`:** These are the click and drag handlers on the guard button the addon lays over locked items at a vendor. They only run when you click or drag, and they just pick the item up the way a normal bag click does.

### Other checks
- **No** loadstring, RunScript, `load`, setfenv or obfuscated strings. No SendMail, trading, auction house or guild bank calls. No SendChatMessage, SendAddonMessage or Battle.net messages. No DeleteCursorItem, macro or key-binding changes, and no logout calls (I searched all files).
- **Player data:** gold and inventory snapshots go only into the `RucksackDB` SavedVariable and show up in your own tooltips and windows. They are never sent to anyone.
- **`Debug.lua`:** It wraps the error handler and still passes every error on to the previous handler. Errors, blocked-action events and info about the game client's API and bank are written to `RucksackDB.debug` on your own disk only. This is harmless.
- **Slash commands (`/rucksack`, `/satchel`):** These change display settings, reset window positions, forget a saved character, or show or clear the error log. Nothing risky.
- **Links:** the only URLs are the author's own GitHub links in CHANGELOG.md.
- **Hidden instructions:** I found no text aimed at an AI or reviewer. The deleted v0.2.4 changelog has a "Co-Authored-By: Claude" commit trailer, which is just a credit line and not an instruction.

### Concerns
None. Every action that moves or sells items is local, starts from a click, and stays inside the player's own bags.

VERDICT: PASS

## Codex

Rucksack combines bags and bank storage into searchable windows, remembers characters’ inventories and gold, sorts items, and provides protected-item controls and junk selling.

Reviewed the release diff, all five Lua files, the manifest and accompanying text, and all seven pre-scan hits. Changes primarily rename Satchel to Rucksack and revise protected-item click handling.

- **Junk sales:** [Rucksack.lua:305](/tmp/packmule-review-rucksack-kwiNQl/addon/builds/Rucksack-v0.2.8-forever/Rucksack/Rucksack.lua:305) checks and calls `SellAllJunkItems`; line 321 calls `UseContainerItem`. Both paths originate from explicit sell-button clicks. The timed fallback checks that the merchant remains open and each item is still the expected, unlocked, unprotected grey item. Closing the merchant cancels pending sales. Normal vendor functionality.
- **Sorting:** [Sort.lua:139](/tmp/packmule-review-rucksack-kwiNQl/addon/builds/Rucksack-v0.2.8-forever/Rucksack/Sort.lua:139) and line 140 call `PickupContainerItem` to rearrange stacks after clicking Sort. The routine excludes protected slots, waits for item locks, and stops on combat, timeout, or an invalid bank interaction. No deletion or transfer to other players.
- **New click guards:** [Window.lua:311](/tmp/packmule-review-rucksack-kwiNQl/addon/builds/Rucksack-v0.2.8-forever/Rucksack/Window.lua:311) and line 319 pick up the player-selected item on left-click or drag. The overlay blocks right-click selling of protected items. Modified clicks retain ordinary item-link/preview behavior.
- **Player data and messages:** [Data.lua:16](/tmp/packmule-review-rucksack-kwiNQl/addon/builds/Rucksack-v0.2.8-forever/Rucksack/Data.lua:16) stores character details, inventories and gold locally in `RucksackDB`. Debug logs likewise remain in saved variables. No addon-message handlers, outbound addon messages, chat sends, whispers or Battle.net sends were found; status messages use local `print`.
- **Commands and execution:** [Rucksack.lua:539](/tmp/packmule-review-rucksack-kwiNQl/addon/builds/Rucksack-v0.2.8-forever/Rucksack/Rucksack.lua:539) registers `/rucksack` and `/satchel` for display settings and local saved-data management. No string-executed code, obfuscated payloads, macro/key-binding changes, forced logout, mail/trade/auction automation, or destructive item APIs were found.

No phishing, reviewer-directed instructions, or external executables/scripts were found. Documentation links point to the author’s project. No malicious behavior identified in this static review.

VERDICT: PASS (nothing malicious)
