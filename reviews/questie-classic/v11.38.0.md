# Questie v11.38.0 security review

**What it does:** Questie is a quest helper for WoW Classic, TBC, WotLK, Cata and MoP. It shows quest givers and objectives on the map, adds tooltips, a quest tracker and a "Journey" log, and can announce quest progress to your party. It also syncs quest data with other Questie users. I found no Lua files outside the addon folder and no executables or scripts in the zip. I didn't read every line of the large data files, so the checks below are based on the prescan hits plus targeted searches of the code.

## Risky behaviours checked

- **Item destruction:** `QuestEventHandler.lua:174` calls `hooksecurefunc("DeleteCursorItem", ...)`. This only observes the call so Questie can refresh quest state, and the line at 177 is a debug message. It doesn't delete anything. **Not a problem.**
- **Chat messages (Questie's own code):**
  - `QuestieAnnounce.lua:199` sends quest progress to PARTY, RAID or INSTANCE_CHAT. This is behind the user's `questAnnounceChannel` setting and the `questieShutUp` option. The text comes from Questie's own announce strings. This is normal behaviour.
  - `QuestieSlash.lua:230` sends a "has completed a total of N quests" EMOTE. It only runs when the player types `/questie flex`.
- **Chat and addon-message hits in `ChatThrottleLib.lua` and `AceComm-3.0.lua`:** This is the standard, unmodified throttling library that wraps the send functions. It only hooks them for rate limiting and is not a problem.
- **Addon messages:** `QuestieComms.lua` and `CommsVisibility.lua` send and receive quest-sync and visibility data through AceComm, on Questie's own prefixes and a "questiecom" channel. The `DailyQuestComms.lua` send calls are commented out. I found no gold, character, or account data being sent, and no mail, trade, auction, or guild bank calls anywhere in the addon's own code.
- **`loadstring` on strings (184 hits):** All of them load static Lua data tables that ship in the zip. There are two kinds:
  - Strings written as `[[return { ... }]]` in files like `classicNpcDB.lua` and the `Localization/lookups/*` files.
  - Strings held in tables defined in the zip's data files, as in `dropDB.lua:41-58`, `zoneDB.lua:40-61`, and `QuestieInit.lua:368` (`LoadDatabase`).

  None of the sources come from addon messages or the network, and I found no built or encoded strings. The `getfenv(0)` hits are in the LibSharedMedia and LibUIDropDownMenu libraries and are standard. The `loadstring` hits in AceAddon and AceBucket are only local aliases. **Not a problem.**
- **Key binding:** `QuestieJourney.lua:215` binds `;` to `QUESTIE_TOGGLE_JOURNEY`, which only toggles Questie's own Journey window. It runs once, only if the key and the action are both unbound. This is benign.
- **Links:** The links I looked at are README badges and wiki, Discord, GitHub and CurseForge pages, plus Wowhead and cmangos URLs in code comments. There are no popups or chat links that send players to other sites. I only checked the first 80 of the link hits that aren't in the Database folder, so I didn't see all of them.
- **Obfuscation:** The prescan flagged 948 very long lines. The Database and Localization data files account for those that I sampled. The escape-sequence and `string.char` matches are in libraries (LibDeflate, AceComm, utf8, compiler). I found no base64 blobs or deliberately unreadable code.
- **Text aimed at a reviewer or AI:** I found none.

## Concerns

None.

## Codex

Questie provides quest tracking, map markers, tooltips, quest history, and group progress sharing. I found no confirmed malicious payload, but one privacy concern prevents a clean pass.

Paths below are relative to `builds/Questie-v11.38.0/Questie/`.

- **Concern — quest-log disclosure:** `Modules/Network/QuestieComms.lua:1041` accepts messages when `sender ~= UnitName("player")`, without checking group membership. At line 941, a request triggers `BroadcastQuestLogV2("QC_ID_BROADCAST_FULL_QUESTLIST", "WHISPER", self.playerName)`. Lines 656–658 check that **the recipient** is grouped; line 1013 sends the reply to the requester. This appears to let an outsider request quest IDs and objective progress. Human validation is needed; this is a privacy flaw, not proof of malicious intent.
- **Gold/items:** No mail, trade, auction, or guild-bank transfer calls found. `Modules/EventHandler/QuestEventHandler.lua:174` uses `hooksecurefunc("DeleteCursorItem", ...)` to refresh quests after deletion; it does not delete items. Optional quest turn-ins use `GetQuestReward(1)` in `Modules/Auto/AutoQuesting.lua:179`.
- **Chat:** `Modules/QuestieAnnounce.lua:199` sends configurable group quest announcements. Item/objective announcements default on (`Modules/Options/QuestieOptionsDefaults.lua:138`). `Modules/QuestieSlash.lua:230` sends an emote only through `/questie flex`. No scam or advertising payload found.
- **Addon messages:** Progress, version, and visibility synchronization are legitimate features, subject to the disclosure concern above. AceComm/ChatThrottleLib supply transport and throttling; their Battle.net wrapper has no Questie caller.
- **String execution:** Loaders in `Modules/QuestieInit.lua:368`, `Database/DropTables/dropDB.lua:41`, `Database/Zones/zoneDB.lua:40`, and localization lookups consume bundled tables. All 198 inspected return-table strings contained literal data. No received-message-to-code execution path found.
- **Bindings, links, packaging:** `Modules/Journey/QuestieJourney.lua:215` binds an unused semicolon to the Journey window. Links are documentation, quest references, or project support prompts. No reviewer-directed instructions or separate executable payloads found. LibDeflate’s filesystem functions belong to its explicitly invoked command-line mode, guarded at `Libs/LibDeflate/LibDeflate.lua:3370`.

Coverage limitation: I traced the risky paths and scanned the complete source tree, but did not complete the requested reading of every code file.

VERDICT: UNSURE (something needs a human to look)
